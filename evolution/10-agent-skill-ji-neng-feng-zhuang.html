工具解决了「单个操作」的复用（MCP 第 06 章），但现实中需要复用的常常是「一整套能力」：不只一个函数，还有配套的 prompt、知识文件、脚本、使用流程。Agent Skills 就是一种轻量级的开放格式，用于把一整套 Agent 能力（prompt、工具脚本、知识文件等）封装为可复用模块，实现低门槛的分享与复用。它本质上约等于一个子 Agent——只是更轻、更结构化、更适合沉淀。Agent Skill 特别适合 SOP 的沉淀和复用，社区里流传着一句很实在的话：「离职的同事终将化作温暖的 Skill」。这一章讲清楚 Skill 的格式、加载机制（渐进式披露）和它与 MCP、子 Agent 的边界。深度版见 Agent 核心 10 · Skill 与渐进式披露。

1. 演进脉络：从「文档」到「能力包」

1.1 背景：技能为什么难沉淀

在 Skill 出现之前，经验沉淀靠两样东西：文档（写了没人读）和代码（可复用但只有能力强的工程师能用）。而 LLM 时代出现了一种新的可能：如果能用「人类可读的文本 + 少量代码」描述一套做法，模型本身就能照着执行——SOP 第一次可以「直接变成可执行的能力」。

1.2 2024.12：Agent Skills 规范提出

2024 年底，Anthropic 提出 Agent Skills 规范（Claude Skills），核心是一个 SKILL.md 文件：用 Markdown 描述能力是什么、怎么用、何时用。配套脚本与知识文件打包成一个目录，即成为一个 Skill。

关键设计（渐进式披露，Progressive Disclosure）：

Skill 不是一次性把全部内容塞进上下文——Agent 先只读取 SKILL.md 的概要，需要时再按需加载细节文件。

这个设计解决了 Agent 能力的「上下文成本」问题：装 50 个 Skill 不意味着 50 份完整内容常驻窗口，而是 50 份「目录卡」+ 按需展开。

1.3 2025-2026：开放生态形成

  • 规范开放：agentskills.io 成为 Skill 的社区仓库与规范中心
  • 平台普及：主流 Agent 框架（Claude Code、Cursor、LangChain 生态等）原生支持 Skill
  • WorkBuddy 等工具把 Skill 作为一等公民：本课程的项目里，Skill 已成为「可复用的操作流程」的标准载体
  • 与 MCP 形成组合：Skill 描述「能力包」（怎么做），MCP 提供「执行通道」（调什么）——一个是大脑里的方法论，一个是手边的工具

2. 核心概念：一个 Skill 长什么样

一个标准 Skill 的结构：

my-skill/
├── SKILL.md          # 能力说明书：做什么、何时用、怎么用（必选）
├── scripts/          # 可执行脚本（可选）
│   └── analyze.py
├── references/       # 参考知识文件（可选，渐进式披露）
│   └── guidelines.md
└── assets/           # 模板、资源（可选）

SKILL.md 的典型结构：

---
name: 课程大纲生成
description: 输入课程主题，输出结构化课程大纲。
  当用户需要课程设计、大纲规划时使用。
---

# 课程大纲生成

## 使用场景
- 新课程立项时需要大纲
- 需要按目标受众调整结构

## 步骤
1. 确认受众与目标
2. 按依赖关系排列模块
3. 每个模块标注章节数与学习时长

## 注意事项
- 模块间必须有依赖关系说明
- 不添加未经验证的营销话术

为什么是 Markdown？ 因为模型对自然语言指令的理解远超对专有格式的理解——SKILL.md 本质上是「写给模型看的 SOP」，人类也能读懂、能 review、能维护。

3. 关键认知：Skill 是什么、不是什么

对比 Skill MCP Server 子 Agent
本质 能力包（方法论+工具+知识） 工具接入通道 独立运行的 Agent
载体 SKILL.md + 文件 协议端点 完整 Agent 实例
适合 SOP 沉淀、能力复用 工具/数据源接入 独立复杂任务
典型例子 「生成课程大纲」 「查询数据库」 「调研竞品」

三个要点：

  1. Skill 约等于子 Agent，但更轻：子 Agent 是完整运行实体（有独立循环、上下文），Skill 是「被激活时的能力包」——Agent 按需加载 Skill，加载后由主 Agent 执行，不产生独立上下文
  2. 渐进式披露是精髓：概要常驻、细节按需——这是 Skill 能规模化（装几十个不爆炸）的原因
  3. SOP 沉淀是杀手锏：把组织里「老师傅的做法」写成 Skill，新员工（或 AI）照着就能做——知识不再流失在人脑里

4. 现状与趋势（2026）

  • Skill 成为 Agent 工程的标准单元：企业开始建设「Skill 库」，像管理代码一样管理能力资产
  • Skill 与 MCP 的分工日益清晰：方法论用 Skill、执行用 MCP，Agent 框架负责两者编排
  • Skill 生态交易：优质 Skill 的分享、交易平台出现——「能力包」开始成为可流通的资产
