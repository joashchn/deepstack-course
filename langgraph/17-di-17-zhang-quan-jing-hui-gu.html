17.1 系统全景

我们的简历筛选系统走过了这样的演进路：

flowchart TD C2[第2章 最小图<br/>extract → summarize] --> C3[第3章 状态+Reducer<br/>多轮评分累加] C3 --> C4[第4章 条件边<br/>解析重试循环] C4 --> C5[第5章 超步<br/>硬/软条件并行] C5 --> C6[第6章 Command<br/>节点内路由] C6 --> C7[第7章 Send<br/>批次简历并行评估] C7 --> C8[第8章 工具调用<br/>查公司/查JD的ReAct] C8 --> C9[第9章 子图<br/>报告生成组件化] C9 --> C10[第10章 多Agent<br/>解析/评估/报告协作] C10 --> C11[第11章 流式<br/>进度与打字机] C11 --> C12[第12章 持久化<br/>会话恢复] C12 --> C13[第13章 时间旅行<br/>取证与实验] C13 --> C14[第14章 中断<br/>offer审批] C14 --> C15[第15章 记忆<br/>裁剪+候选人画像] C15 --> C16[第16章 容错<br/>重试/超时/降级/重跑]

把最终形态的运行时结构画成一张分层图——这是本书的总图：

flowchart TB subgraph L1[能力层：LangChain] M[模型接入] MSG[消息构造] TOOL[工具定义 @tool] end subgraph L2[编排层：LangGraph 核心] N[节点] E[边/条件边/Command] S[状态 + Reducer] SD[Send 动态扇出] end subgraph L3[运行时层] SS[超步引擎 Pregel] ST[stream 流式] RK[RetryPolicy] end subgraph L4[持久层] CK[Checkpointer<br/>线程/检查点/中断恢复/时间旅行] STORE[Store<br/>跨线程长期记忆] end subgraph L5[协作层] SUB[子图] MULTI[多Agent拓扑] end L1 --> L2 --> L3 --> L4 L2 --> L5

五层各司其职：LangChain 提供单次能力；核心机制把能力组织成图；运行时负责执行、流式与容错；持久层把执行变成可恢复、可回溯、可记忆的；协作层用子图与多 Agent 应对规模化复杂度。

17.3 贯穿全书的六条心法

比 API 更值钱的是反复出现的设计判断，收拢成六条：

一、控制流尽量画进图里（第 4 章）。能被看见的流程才能被观测、重跑、恢复。节点内部的私有 if 是图的盲区。

二、并行写必有 reducer（第 3、5、7 章）。多个节点（尤其同超步、Send 实例）写同一字段是常态而非意外，合并语义是状态定义的一部分。默认覆盖只属于单写者。

三、节点是纯函数式的（第 3、14、16 章）。读状态、返补丁；副作用要幂等或后置——重试、中断恢复、时间旅行全都依赖这条纪律。reducer 要纯、路由函数要哑，同理。

四、语义并行不等于物理并行（第 5 章）。同超步只承诺快照隔离，不承诺并发执行。要真实的并发收益，用异步节点与 astream。

五、一切高级特性都长在持久化上（第 12~15 章）。会话恢复、时间旅行、中断、长期记忆——没有检查点这棵树，一根枝都活不了。生产系统的第一步是挂 checkpointer。

六、先单图后多 Agent（第 10 章）。多 Agent 是复杂度的管理手段不是智能的来源。prompt 膨胀、工具过载、子图复用三个信号都没亮之前，加层只会加乱。

17.4 本书没讲什么

诚实的边界与继续前行的路标：

  • LangGraph Platform / Agent Server。图的托管运行时：Assistant/Thread/Run/Cron 等 API、A2A 与 MCP 协议、Studio 可视化调试。本书聚焦框架本身，部署形态属平台层。当你需要把图变成多人共用的服务时再去学——好消息是底层协议（thread、checkpointer、stream）你已全部掌握。
  • deepagents 等高层范式。在 LangGraph 之上再封装的 Agent 范式（规划-执行-反思）。懂了本书的积木，那些框架会从"魔法"变成"显然"。
  • 性能调优。大扇出的并发参数、Postgres 检查点的索引策略、流式背压的精细化处理——生产化之后按需深入。
  • 评测（Evals）。怎么科学地衡量"图改了之后效果变好还是变坏"。时间旅行（第 13 章）给了你做回归实验的原料，但系统的评测方法学值得专门一本书。

17.5 结业练习：把它真正跑起来

最后一个大作业，检验全书成色：

从零实现"候选人复投评估系统"，要求： 1. 单份评估是 ReAct 子图（工具：查 JD、查公司、查历史评估） 2. 批次评估用 Send 扇出，进度用自定义流推送 3. 综合分超 85 触发 interrupt 人工审批，超时 48 小时自动驳回（服务层 TTL） 4. 评估结论写入 Store 的候选人命名空间，复投时注入历史画像 5. 挂 Postgres checkpointer，演示：中断恢复、从失败检查点重跑、fork 对比两次评估 6. 外部工具故障率 20%：用 RetryPolicy + 兜底节点保证整批流程总能出报告

完成它，你就拥有了一个可以直接写进简历的项目——以及更重要的是，其中每一块你都知道为什么在那里。

十七章、一个系统、一套心智模型。LangGraph 的文档会更新，API 会变迁，但"显式控制流 + 快照化状态 + 超步执行"这三个核心思想短期内不会过时。带着它们去读任何工作流框架（乃至任何分布式系统），都会顺利得多。

祝构建愉快。
