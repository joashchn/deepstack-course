AI 框架篇（框架实战）

8 模块

课程不从框架 API 开始背，而是围绕一个持续演进的「生产事故调查与修复建议 Agent」，先让学员亲手看到最小 Agent Loop 会怎样失控，再逐步引入 LangChain、LangGraph、OpenAI Agents SDK、Pi、Deep Agents 与 Python Mini Harness，理解每一层框架在什么背景下出现、解决什么问题、又留下了哪些工程责任。最终让学员具备三种能力：能把 Agent 跑起来、能把长流程做可靠、能把项目讲清楚并交付出去。

模块一

从 LLM 调用到 Agent Runtime

目标：先理解 Agent 的底层执行过程，再学框架。

一次模型调用为什么不是 Agent；手写最小 Agent Loop；最大轮次 / 超时 / 完成标准 / 无进展检测；Provider Adapter 与 Trace。

项目结果：具备停止、校验、幂等、Provider Adapter 和 Trace 的最小 Agent Runtime。
模块二

LangChain 为何出现

目标：理解胶水代码的来源与抽象收益。

多 Provider / 多消息 / 多工具带来的重复接线；模型 / 消息 / 工具 / 输出抽象；Tool Schema 契约；用 create_agent 重写手写 Loop。

项目结果：一版使用 LangChain v1 现代入口实现的事故调查 Agent。
模块三

LangChain v1 与抽象的代价

目标：抽象泄漏后如何定位问题。

create_agent 与 LangGraph Runtime 分层；Middleware 实现日志 / 策略 / 上下文处理；动态 Prompt 与敏感信息遮蔽；分层 Trace 定位泄漏。

项目结果：带 Middleware、动态工具策略与分层 Trace 的 LangChain Agent。
模块四

LangGraph：让状态与控制流显式

目标：把流程状态迁移为可检查、可测试的显式图。

State 与 Prompt / History 区别；Node 局部更新 + Reducer 合并；条件 Edge；并行分支与状态聚合；节点 / 路由 / 快照测试。

项目结果：含业务节点、Agent 节点、条件路由、并行取证的 LangGraph 事故调查图。
模块五

LangGraph：生产级长流程

目标：让显式图具备持久化、暂停、恢复能力。

Checkpoint / Thread / Store 职责；跨进程恢复；Interrupt / Resume / 审批；节点重放与幂等；Streaming 与预算控制；故障注入验证。

项目结果：可暂停、可恢复、支持审批、幂等、Streaming 和预算控制的长流程。
模块六

OpenAI Agents SDK

目标：更轻量的 Python Agent SDK 与边界认知。

开源 SDK / 远端模型服务 / 完整 Harness 区别；Agent / Runner / Function Tool；指向千问兼容端点；Guardrail / Tracing；Handoff 选择。

项目结果：可接入国产兼容模型、保留本地观测的轻量工具 Agent。

从 Agent Runtime 到 Python Mini Harness

PROJECT 02

基础客服机器人

后端 Spring Boot（Java 17）· 前端 React 18 · Agent/工具调用 Python
14 个工程难点 · 面试题导向
七段式 · 示例难点 01：长对话下模型「失忆」

背景：上下文有上限，多轮对话历史越拼越长，顶到窗口天花板后早期消息被静默截掉，模型像「失忆」。

方案：三层处理——滑动窗口（只留最近 N 轮）+ 历史摘要（小模型压成摘要挂 prompt 前）+ 长期记忆（用户画像/偏好结构化字段每轮带）。最终结构：系统提示 + 长期记忆 + 历史摘要 + 最近 N 轮 + 当前问题。

→ 后端 Spring Boot 实现 ChatContextService，前端无需感知分层。

PROJECT 03

workflow 型智能体

后端 Spring Boot · 前端 React 18 · 编排 Python（LangGraph + Pydantic）· 进程隔离
16 个工程难点 · 面试题导向
七段式 · 示例难点 01：工作流的状态中枢

背景：工作流是多节点链路，前一节点产出要给后面多节点消费；朴素做法各存各的、靠参数层层递，链路一长就乱。

方案：统一 State 对象贯穿全流程；节点即纯函数（只返回要更新的字段，由框架按 reducer 合并）；显式合并策略（覆盖 / 追加）；状态快照便于调试恢复。Java 主服务经 HTTP 调独立 Python 编排服务，进程隔离——编排异常不影响主链路。

→ Python 用 TypedDict + Annotated 定义带 reducer 的 State，React 按字段渲染各阶段产物。

  • 09 幂等键设计——重试不重复扣款

PROJECT 04

通用型 Agent

后端与编排统一 Python（FastAPI + LangGraph 同进程）· 前端 React 18
21 个工程难点 · 七层递进 · 面试题导向
七段式 · 示例难点 01：复杂目标的自主拆解

背景：接到「做一份竞品分析并写成报告」这类大目标，模型一次性端到端生成必漏环节、文件没存、引用编造——因为缺可逐步执行、可校验的计划。

方案：结构化规划节点输出 Pydantic 校验的 Plan（每子任务带 id / 描述 / 依赖 / 产物要求 / 验收条件）；独立校验节点查依赖成环、产物为空、漏「汇总」步；校验失败带错误重拆而非放行；计划作 LangGraph 编排骨架，产物落库可续读。
